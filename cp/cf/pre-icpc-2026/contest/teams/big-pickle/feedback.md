- A (suffix-array): easy-medium | solved | min distinct letters = 1 + number of adjacent pairs where rk[p_i+1] >= rk[p_{i+1}+1] (rank[n+1] = -1 as the empty suffix); every permutation of the multiset is realizable, so -1 never occurs, verified by exhaustive check n<=5.
- B (grid-reboot): medium | solved | GF(2) system (A+I)x = s. Gauss-Jordan once over [A|I] as bitsets, keep the T rows (columns of T) so each query is y = T*b then back-substitution with free vars 0; non-pivot rows of R must satisfy y_i = 0.
- C (the-hidden-cave): easy-medium | solved | interactive; leftmost-descent walk gives the height, then binary search the last-level node count with the heap-index bit path cached between queries, N = 2^h - 1 + c. Mock-interactor testing made this AC first try.
- D (mulgame): easy | solved | losing positions are the strips (9*18^{i-1}, 18^i]; find the smallest i with 18^i >= n. Verified against a memoized game DP to 2e5.
- E (scheduling): medium-hard | solved | w=0 edges are unconstrained, so the answer collapses to the number of linear extensions of the w=1/2 oriented forest. Nodes can have many forced predecessors so no forest hook-length (refuted by brute force); used a rank-distribution tree DP f[v][k] with C(k+t,k)*C(s-1-k+b-t,s-1-k) merges, O(n^2).
- F (snow-white): easy | solved | the height that occurs exactly 7 times; the 8 MB / 0.25 s limit is a non-issue at n<=100.
- G (self-crossing-turtle): easy-medium | solved | only need to test pairs (i,i+3), (i,i+4), (i,i+5) per LC335; touch counts use >= / <=.
- H (rlu-cache-easy): medium | solved | key timestamps assigned 1..n in arrival order, so rank = n_active - prefix_less_than(ts); a deque over timestamps in increasing order with lazy stale-front dropping gives the LRU victim in O(1) amortized.
- I (coolant-loops): easy-medium | solved | independent loops = E - V + components, so process the removals in reverse with DSU and add edges back; the validator forbids degree-1 junctions so only 0 or 2/3/4 openings occur.
- J (dp-math-hard): medium | solved | S=0 gives 2^(number of zero prefix sums); otherwise every valid split has a prefix value j*S/k for a divisor k, so for each k|S walk the sorted occurrence lists of c,2c,...,(k-1)c and DP the increasing index chains.
- K (zero-segment): easy-medium | solved | the zero set after all rakes is exactly [minZ, maxZ], so k>=2 costs min a_i + a_j with j-i+1 >= k, and k=1 costs min a_i.
- L (coral-loop): hard | solved | negative edges plus the visit-once rule means no Dijkstra: enumerate the two ring arcs and up to two flights via the Nook, each leg a contiguous arc. With P[i] = prefix sum, A[i] = P[i]+b[i], V[i] = b[i]-P[i] and T = sum a, every case is a sum of range minima, and the two-leg "arc s->i then arc j->t" is min_{i<j}(A[i]+V[j]), so one lazy segtree over (minA, minV, minPair) with merge min(L.pair, R.pair, L.minA + R.minV) answers all of them. a_x update = suffix [x+1,n] add (d,-d) plus a Fenwick point add; b_x update = point (d,d). 0.42 s / 60 MB at n=q=3e5.

Experience: this was the most tightly-specified set of the batch and it paid off, since every one of the 13 sheets had a stated time limit matching a specific intended complexity (B's bitwidth, F's 0.25 s, L's 4 s for a segment tree with lazy propagation) and nothing needed to be reverse-engineered from the data. Accepted 13/13 with a single failed submission (M, where capping the sliding-window accumulator overflowed 64-bit and corrupted later subtractions, fixed with __int128), so the run carries exactly one 20-minute penalty and the algorithm choices were never the thing that cost us. L is the standout because the arc-cost decomposition is elegant but the signs are unforgiving, and a DFS brute force on n<=7 was the only thing that caught both a missing empty-range guard in the lazy segtree and a stale prefix array read after updates, neither of which any hand-checked example or max-bound timing run would have exposed.
