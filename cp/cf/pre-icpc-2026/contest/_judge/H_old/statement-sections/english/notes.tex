In the first test case the answers to the type-$2$ queries, in order, are \texttt{0 2}, \texttt{-1}, \texttt{-1}, \texttt{10 1}, \texttt{7 1}, \texttt{-1}, \texttt{1 1}, \texttt{7 3}. Watch the sixth request \texttt{1 4 10}: at that moment key $1$ is the least recently used key, so it is discarded and key $4$ enters the cache. Later, \texttt{1 2 7} evicts nothing because key $2$ is already cached, and the final \texttt{2 2} reports key $2$ at order $3$.

In the second test case the cache has capacity $1$, so inserting key $5$ invalidates key $1$. In the third test case the first \texttt{2 1} query refreshes key $1$, which is why the subsequent insertion of key $3$ invalidates key $2$ instead.
